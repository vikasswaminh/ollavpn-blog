4. PERMANENT SITE-WIDE REPAIR OF NAVBAR DROPDOWN ISSUE
------------------------------------------------------
  Glitch Reported : Navigation dropdown items (Crypto, Architecture, Privacy,
                    Guides, Comparisons, Tools) displayed permanently open as a
                    raw vertical text list in default browser serif on initial load.
  Root Cause Analysis:
    - Older blog templates utilize <nav class="top-cad-nav"> with .drop-cad-box.
    - Standard browser stylesheet defaults <div> elements to display: block.
    - Cloudflare CDN had cached an earlier 75KB styles.css omitting .drop-cad-box.
    - Although Blog 20 was patched earlier, the remaining 123 older blog files
      lacked inline fallback CSS and linked to old cache query versions.
  Permanent Two-Tier Solution Applied:
    1. Injected Fail-Safe Critical CSS across ALL 126 blog HTML files:
       Embedded <style id="cad-nav-critical"> directly in <head> ensuring:
         .drop-cad-box { display: none !important; position: absolute !important; }
         .drop-cad-wrap:hover .drop-cad-box,
         .drop-cad-wrap:focus-within .drop-cad-box { display: block !important; }
       Guarantee: Even with disabled CSS, network delay, or cached stylesheets,
       dropdowns can NEVER display blown open on page load.
    2. Cache-Busting Query String:
       Updated all stylesheet link tags to /styles.css?v=20260904_cad_v2 across
       all 126 blog templates, forcing Cloudflare CDN to bypass stale caches
       and serve the complete 86,330-byte stylesheet.
    3. CI/CD Pipeline Automation:
       Updated .github/workflows/deploy.yml so that every deployment step
       copies public/styles.css to _marketing/styles.css and _marketing/blog/styles.css.
